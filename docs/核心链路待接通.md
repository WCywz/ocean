# 核心链路待接通

> 调度引擎、版本管理、运行监控全套基建已就绪，但数据流入和模型推理两条核心链路仍未接通——系统在空跑。

---

## 问题 1：ModelForecastJob 是假的

**位置：** [ModelForecastJob.java:53](ocean-server/src/main/java/com/ocean/task/ModelForecastJob.java#L53)

```java
// TODO: 调用模型预测逻辑
// 目前占位：模拟执行
Thread.sleep(1000);
```

定时调度触发后，Job 休眠 1 秒就直接标记 SUCCESS。没有调 Python，没有产出 forecast_grid 数据。所有显示"运行成功"的定时预报记录都是空的。

**需要做：** 接入真实的 Python 模型推理调用（类似 `ForecastServiceImpl.runForecast()` 的 `ProcessBuilder` 方式）。

---

## 问题 2：数据摄入全程手动

**位置：** [scripts/ingest_daily.py](scripts/ingest_daily.py) + [scripts/ingest_raw_daily.py](scripts/ingest_raw_daily.py)

当前链路：

```
CMEMS → 手动下载 CSV → 手动跑 ingest 脚本 → MySQL
```

两个 Python 脚本都需要手动传 `--csv` 或 `--data-dir` 路径执行。没有自动拉取 CMEMS，没有定时摄入。

**需要做：**
- CMEMS 数据自动拉取（MOTU API 或 Copernicus Marine Toolkit）
- 拉取后自动触发摄入脚本（或直接写入 MySQL）
- 可与现有 `SystemDateTask` 管道整合，也可作为独立定时任务

---

## 问题 3：runForecast() 硬编码 versionId=1L

**位置：** [ForecastServiceImpl.java:338](ocean-server/src/main/java/com/ocean/service/impl/ForecastServiceImpl.java#L338)

```java
g.setVersionId(1L);
```

即使手动触发预报（`POST /api/forecast/run` 或管道自动触发），所有 forecast_grid 结果都挂到 versionId=1，多版本调度的运行记录无法与预测结果关联。版本管理形同虚设。

**需要做：** runForecast() 接受 versionId 参数，把结果写到正确的版本。

---

## 三者关系

```
数据摄入自动化 ──→ 观测数据到位 ──→ ModelForecastJob 调 Python ──→ forecast_grid
                                                                       ↑
                                                              runForecast 需要 versionId 参数
```

三条全修完，系统才从"能看"变成"能用"。
