# 海洋预报模型集成管理 — 需求文档

> 本文档描述"模型集成管理"模块最终要实现的效果。
> 阅读对象：开发人员。读完就知道系统做完后是什么样子。

---

## 一、这个模块是干什么的

把海洋预报模型从"实验脚本"变成"可运营的生产服务"。

**不包含：** 在线训练模型、GPU 调度、调参实验。模型是线下训练好之后注册到系统里的。

---

## 二、最终效果总览

运维人员打开网页，就能完成以下全部操作：

1. 注册和管理模型的基本信息
2. 配置每个模型版本的运行参数（结构化的表单，不手写 JSON）
3. 设置每个版本的定时执行计划
4. 查看每个版本的运行状态和历史记录
5. 模型跑失败了自动收到通知

**全过程不写代码、不连服务器。**

### 模块 3：业务化运行设置

**做什么：** 每个版本有自己的执行时间表，系统按各自的时间表自动触发执行。

**效果：**

```
SST 预报 v3   每天 06:00 跑    ✓ 自动执行
CHL 预报 v1   每天 08:00 跑    ✓ 自动执行
盐度预报 v1   每周一 06:00 跑  ✓ 自动执行
```

- 版本创建时在表单里选好执行时间（或者用 cron 自定义）
- 保存后调度引擎自动接管，不需要额外操作
- 修改调度时间后下次立即生效

**数据存储：** 每个 `model_version` 的 `cron_expression` 字段被**调度引擎实际读取和执行**。

| cron 表达式 | 含义 |
|-------------|------|
| `0 0 6 * * ?` | 每天早上 6:00 |
| `0 0 8 * * ?` | 每天早上 8:00 |
| `0 0 6 * * MON` | 每周一早上 6:00 |
| `0 0 */6 * * ?` | 每 6 小时一次 |

**实现要点：** 需要在后端引入一个调度框架（如 Quartz），启动时从数据库读取所有 RUNNING 状态的版本及其 cron，动态注册到调度器中执行。

### 模块 5：异常告警

**做什么：** 模型跑失败了，系统自动通知，不用人盯着监控面板看。

**告警规则：**

| 触发条件 | 通知方式 |
|----------|----------|
| 模型执行失败（状态 = FAILED） | 站内通知 + 可选：短信/邮件 |
| 模型连续失败 3 次 | 站内通知 + 标红提醒 |
| 模型执行超时（超过预期时间 N 倍） | 站内通知 |

**效果：**

```
┌──────────────────────────────────────┐
│  🔔 系统通知                     [×]  │
│                                       │
│  ⚠ SST v3 今日 06:00 执行失败         │
│    错误：输入数据缺失                   │
│    时间：2025-06-15 06:05              │
│    [查看日志]                          │
│                                       │
│  ⚠ CHL v1 已连续失败 3 次              │
│    需要人工排查                         │
│    [查看日志]                          │
└──────────────────────────────────────┘
```

**实现要点：** 模型执行完成后，检查状态。如果是 FAILED，触发告警流程。可以复用系统已有的 `alert_rule` / `alert_event` 表结构。

## 四、数据关系总图

```
model（模型 — 逻辑实体）
  ├── id
  ├── model_name      "SST 海温预报模型"
  ├── model_type      "SST"
  └── description

       │ 1:N
       ▼

model_version（版本 — 可运行的配置 + 调度）
  ├── id
  ├── model_id        → model.id
  ├── version_label   "v3.0"
  ├── params_config   JSON（模型结构 + 数据参数）
  ├── cron_expression 调度时间
  ├── data_source     数据来源
  └── status          手动启用/停用

       │ 1:N
       ▼

model_run_log（运行日志 — 每次执行的记录）
  ├── id
  ├── version_id      → model_version.id
  ├── start_time      开始时间
  ├── end_time        结束时间
  ├── duration_ms     耗时
  ├── status          SUCCESS / FAILED / RUNNING
  ├── error_message   错误信息
  └── log_text        详细日志
```

## 五、你现在系统的情况

| 模块 | 当前状态 | 缺什么 |
|------|---------|--------|
| 模型信息维护 | **基本可用** | 界面可以再完善，但核心功能已经有了 |
| 模型参数配置 | **有壳** | 参数是自由 JSON 文本框，没有结构化表单 |
| 业务化运行设置 | **没接通** | cron 字段存了但调度引擎没读取，所有模型固定凌晨跑 |
| 运行状态监控 | **没有** | 没有运行日志表，状态是手动切换的，不是系统自动写的 |
| 异常告警 | **没有** | 告警模块存在但未与模型执行联动 |

## 六、总结

最终目标一句话：

> **模型从注册、配置、定时执行，到状态监控、异常告警，全在网页上完成，不需要写代码、不需要连服务器。**

就像一个"模型管家"——你告诉它谁、怎么跑、几点跑，它自动帮你安排好，跑完告诉你结果，跑挂了你不用去查日志就知道哪里出了问题。
